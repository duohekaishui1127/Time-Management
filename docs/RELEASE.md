# 发布检查

代码仓库提供静态预检与自动测试，不能代替微信开发者工具上传、真机验证及公众平台审核。当前仓库保留了演示 AppID 和 `latest` 基础库版本，因此 `npm run release:check` 会明确失败；接入正式账号并实测后再替换。

## 1. 配置

1. 在 [project.config.json](../project.config.json) 填入自己的小游戏 AppID。选择已在目标真机验证的基础库版本，替换 `libVersion: "latest"`；保持 `setting.minified: true` 和 `setting.urlCheck: true`。
2. 如果需要广告提前解锁，在 [src/config.js](../src/config.js) 填写该小游戏的激励视频广告位 ID。未配置时关卡只提供正常通关解锁；开发者工具的模拟广告不会在真机提供奖励。
3. 在公众平台确认小游戏资料、类目、隐私说明及广告相关设置。项目调用本地存储、分享、振动、系统信息和可选的激励视频 API；没有登录、定位、相机、麦克风或自建网络请求。若增加这些能力，重新核对平台声明和用户说明。

## 2. 自动检查

```bash
npm run release:check
```

该命令先验证 40 关的数据、可解性和回归测试，再检查 AppID、基础库版本、压缩配置及广告配置提示。以 `v` 开头的 Git 标签会在 CI 中额外执行发布配置预检。静态检查无法判断 AppID、广告位是否真实可用，也无法完成平台审核。

## 3. 真机验收

至少在不同屏高的 Android 与 iPhone 上逐项检查：

- 首次启动、横竖屏限制、刘海和底部安全区、窗口尺寸变化；关卡列表、六任务卡片和结果时间线均可点击。
- 关卡 1、3、10、11、20、30、40 的成功与失败、三星评分、返回、重试、分享关卡进入；第 3 关通关后应解锁第 4 关。
- 关闭后重开存档，旧版本存档迁移；设备存储异常时应有提示，不能静默丢失进度。
- 如启用广告：完整观看、提前关闭、加载失败、无网络及超时。只有完整观看能解锁，重新启动后仍应保留解锁。
- 分享入口和卡片文案、开发者工具控制台错误、包体体积与首屏加载时间。

## 4. 发版记录

发布前记录测试设备和微信版本、基础库版本、AppID 对应环境、广告位、提交哈希以及审核结果。关卡 ID 和存档键发布后保持稳定；修改旧关卡顺序、解锁规则或评分时，要用旧存档回归测试。旧客户端遇到更高版本的同键存档时会只读，避免回退版本覆盖新存档。上传候选版本前，可为候选提交打 `vX.Y.Z-rc.N` 标签触发 CI 预检；审核通过并发布后，再为对应提交打 `vX.Y.Z` 标签。
